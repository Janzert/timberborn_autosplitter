Captures a snapshot of Timberborn's memory for offline testing.

    tb-dump [options]              (the installed copy, with the capability)
    cargo dump -- [options]        (from this repo, without it)

Options:
  --state <id>     What game state this capture is of. This is what tests search
                   on -- they ask for a state, never for a directory -- so a
                   capture without one will never be found. May be repeated;
                   the known ones are listed at the end of this help.
  --label <name>   Names the snapshot directory, after the build id. Defaults to
                   the first --state. Only cosmetic; nothing searches on it.
  --notes <text>   Free text recorded in the manifest: faction, day, what is on
                   screen. A snapshot nobody can identify later is wasted.
  --pid <pid>      Capture this process instead of searching for the game.
  --freeze         SIGSTOP the game for the duration of the read, so every
                   range comes from the same instant. Without it the last range
                   is seconds younger than the first, and the capture can hold a
                   combination of values the game never had. The game is stopped
                   for as long as the capture takes, around 6s for 5 GiB, so do
                   not do this during a run that matters.
  --dry-run        Report what would be captured and write nothing.
  --help           This.

The game must already be running. This needs no privilege of its own: when a
direct open is refused it runs tb-ptrace-open, which holds the capability.
Install that once:

    cargo install --path tb-ptrace-open --root ~/.local \
      && sudo setcap cap_sys_ptrace+ep ~/.local/bin/tb-ptrace-open

The helper refuses any process with no Timberborn data mapped, so a mistyped
--pid cannot read something else.

Snapshots land in <repo>/snapshots, overridable with TIMBERBORN_SNAPSHOTS.
They are large and are never committed.
