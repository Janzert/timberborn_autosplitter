Captures a snapshot of Timberborn's memory for offline testing.

    tb-dump [options]              (the installed copy, with the capability)
    cargo dump -- [options]        (from this repo, without it)

Options:
  --label <name>   Names the snapshot directory, after the build id. Say what
                   state the game is in: "folktails-loaded", "wonder-unlocked".
  --notes <text>   Free text recorded in the manifest: faction, day, what is on
                   screen. A snapshot nobody can identify later is wasted.
  --pid <pid>      Capture this process instead of searching for the game.
  --dry-run        Report what would be captured and write nothing.
  --help           This.

The game must already be running. Reading its memory needs ptrace rights,
granted to an installed copy rather than to the whole machine:

    cargo install --path test-harness --bin tb-dump --root ~/.local
    sudo setcap cap_sys_ptrace+ep ~/.local/bin/tb-dump

The capability is an attribute of the file: it survives reboots, but is lost
whenever the binary is rebuilt, so a reinstall needs the setcap again.

Any process with nothing mapped from the Timberborn install is refused, so a
mistyped --pid cannot read something else.

Snapshots land in <repo>/snapshots, overridable with TIMBERBORN_SNAPSHOTS.
They are large and are never committed.
